# nishtyak

Python-ядро кейса 03 Обнинского хакатона 2026: статический анализ научного проекта и подготовка пакета для повторного запуска.

## Запуск

Требуется Python 3.11 или новее.

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev]'
nishtyak analyze tests/fixtures/local_project
nishtyak build tests/fixtures/local_project --entry main.py \
  --python 3.11 --data 'data.csv: значения 2, 4, 6' \
  --expected 'mean=4.00' --output /tmp/local-project.zip
```

На Windows окружение активируется через `.venv\Scripts\activate`. CLI выводит JSON. Для базовой библиотеки достаточно `pip install -e .`; чтение Conda требует дополнительной зависимости `.[conda]`, также входящей в `.[dev]`.

## Подключение

Публичная точка входа — `ReproducibilityService`: `analyze` → `prepare` → `render`. ZIP собирает отдельный `BundleWriter`. Реализованы библиотека, CLI и самостоятельный внутренний HTTP-сервис с очередью, хранением, ownership и TTL. Пользовательский backend обращается к нему по Bearer + X-Owner-ID.

## Сервис логики

```sh
python -m pip install -e '.[service]'
export NISHTYAK_SERVICE_TOKEN=$(python -c 'import secrets; print(secrets.token_hex(32))')
nishtyak-service dev --port 8010
```

`dev` запускает HTTP и очередь на собственных тестовых проектах через subprocess. Серверный профиль: `deploy/service-compose.yaml`, отдельный диспетчер и offline-контейнер на анализ. Команды развертывания и проверки — в [серверной спецификации](docs/SERVER_RUNTIME.md), ручки для внешних интеграций — в [API-контракте](docs/API_CONTRACT.md).

## Веб-интерфейс

Фронтенд из ветки `web` объединён с сервисом: Vue 3, TypeScript, Vite, Pinia. Загрузка, анализ, сохранение решений и скачивание ZIP работают через HTTP. Режим `accounts` добавляет регистрацию, вход, профиль, личное пространство, команды, роли и одноразовые приглашения. Производственные моки аккаунтов и команд удалены.

Для локальной проверки установите `pip install -e '.[service,web,dev]'` и `npm ci`. Запустите три процесса с одинаковым серверным `NISHTYAK_SERVICE_TOKEN` у двух Python-процессов:

```sh
nishtyak-service dev --port 8010
nishtyak-web --port 8020
npm run dev
```

Откройте `http://127.0.0.1:5173`. Vite направляет `/api` в браузерный шлюз на 8020. Локальный режим явно обозначен, не требует входа и использует одну рабочую область через loopback. Для настоящих аккаунтов нужен режим `accounts` и точный HTTPS-origin. Внутренний API и ключ DeepSeek не передаются браузеру; переменные `VITE_*` не должны содержать секретов.

`npm run build` проверяет типы и собирает `dist`; `npm test` проверяет сохранение и переключение проектов. Для сервера предусмотрен отдельный ограниченный контейнер `deploy/web-compose.yaml`: интерфейс и `/api` доступны на loopback-порту 8081. [Развертывание и режимы авторизации](docs/SERVER_RUNTIME.md), [контракт шлюза](docs/API_CONTRACT.md).

В режиме `accounts` пользователь регистрируется с именем, email и паролем, создаёт команду и выдаёт приглашение с ролью. Ссылка действует семь дней и принимается один раз; её можно отозвать. Приглашённый входит или регистрируется, после чего присоединяется к команде. Пароли хешируются Argon2id, сессии хранятся на сервере. Права на проекты проверяются при каждом запросе, включая скачивание. Отправка писем, подтверждение email и восстановление пароля пока не реализованы; ссылку передают самостоятельно.

Для публичного HTTPS используется `deploy/preview-compose.yaml` с `NISHTYAK_WEB_MODE=accounts` и `NISHTYAK_WEB_ORIGINS`. Старый режим `preview` с общим кодом остаётся отдельным демонстрационным профилем. При переходе на аккаунты прежние общие проекты никому автоматически не присваиваются. [Настройка серверного профиля](docs/SERVER_RUNTIME.md).

Сырые проекты доступны через кнопки на странице загрузки и в `public/examples`: `scientific-measurements.zip` (два Python-файла с NumPy/pandas и локальным модулем) и `local-calibration.zip` (два Python-файла с локальным модулем). В ZIP нет данных, README, requirements, pyproject, лицензии или готовых результатов. Оба обращаются к отсутствующему `measurements.csv`: анализ находит зависимости и запуск, формирует черновик и предупреждает о недостающих данных и неизвестной среде. Эти примеры намеренно не запускаются до добавления данных. Состав и хеши — в `public/examples/manifest.json`; исходники — в `examples/upload-projects/`.

Путь пользователя: загрузка → уточнение и проверка → скачивание. На втором шаге показаны описание проекта, найденная команда и зависимости. Перед сборкой можно уточнить отсутствующие данные, известную версию Python, неоднозначный запуск или соответствие импорт → пакет. Неизвестное разрешено оставить в отчёте; main, точные версии и подтверждение данных не обязательны для черновика. Ответы сохраняются, план пересчитывается; «Собрать ZIP» сначала синхронизирует последние изменения. На финальном экране — архив и краткие остаточные ограничения без повторного опроса. Подробные свидетельства сохраняются в `analysis-report.json`.

DeepSeek работает в фоне: в одном ограниченном цикле готовит описание README и выбирает точку входа среди проверенных статических кандидатов. Модель получает отфильтрованные исходники и карту проекта; уведомление показано перед загрузкой. При недоступности API, отсутствии ключа или невалидном выборе используется статический способ. Явное описание и команда автора имеют приоритет. Модель не подтверждает данные и версии и не исполняет код. Реальные ошибки состава, секретов и выбранного запуска по-прежнему блокируют экспорт.

## Дополнительные функции

```sh
nishtyak environment > /tmp/author-environment.json
nishtyak analyze /path/to/project --author-environment /tmp/author-environment.json
nishtyak conda /path/to/project
nishtyak build tests/fixtures/local_project --entry main.py --python 3.11 \
  --data 'data.csv' --docker --output /tmp/local-project-docker.zip
```

DeepSeek подключается через серверные переменные `DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL`; необязательный `DEEPSEEK_BASE_URL` по умолчанию равен `https://api.deepseek.com`. `NISHTYAK_AUTOMATIC_REVIEW=1` включает фоновое описание и выбор запуска новых загрузок и явно повторяемого анализа. Без этой настройки библиотека и сервис работают статически. На автоматический разбор отводится до 15 секунд; при ошибке или превышении бюджета доступен обычный пакет. Результат кешируется по анализу, чтение страницы и повторная сборка не вызывают модель заново.

```sh
nishtyak advise /path/to/project --feature explain
```

Отдельный CLI-советник сохранён для интеграций: `explain`, `readme`, `packages`. Его гипотезы не меняют зависимости автоматически. Недоступность API не мешает основному сценарию.

## Проверки

```sh
pytest -q
ruff check src tests
ruff format --check src tests
```

Текущий результат: 771 Python-тест, 87 тестов фронта, проверка типов, production build, Ruff и форматирование проходят. Браузерный сценарий `.py`/ZIP, удаление, граф, lock, Dockerfile и живой DeepSeek проверены через собранный интерфейс на VM. Решения, lock и байты архива сохранились после рестарта шлюза. [Веб-приемка](examples/web-verification.json).

v0.3.0 развернут на VM: 38 проверок изоляции и 32 HTTP-проверки, совпадение OpenAPI и установленного кода. Два подготовленных проекта (NumPy/Pandas и локальный модуль) прошли автоматический выбор запуска, uv lock, экспорт и повторение в чистых Python 3.11 окружениях с результатом `4.0`. Живой DeepSeek проверен для запуска и README. Lock и решения пережили перезапуск, повторный анализ удаляет прежний lock. [Результаты приемки ядра](examples/resolution-verification.json). Загруженный пользовательский код сервис не выполняет.

v0.3.0 добавляет полный статический граф локальных импортов, stdlib выбранного Python, запуск без обязательного main, объяснимый черновик без лишних обязательных полей, wheel-only lock с хешами и DeepSeek с ограниченными инструментами чтения. Lock — новый согласованный набор под выбранные Python/OS, а не восстановленная среда автора. Контракт новых ручек и SDK описан в [API_CONTRACT.md](docs/API_CONTRACT.md).

Версия 0.2.0 добавляет выбор корня ZIP и `src`, декларации зависимостей/extras, запуск `module:function`, среду автора через HTTP и изолированный worker, сохранение решений с ревизией и повторный анализ исходного ZIP. Для второго backend в wheel входит `nishtyak_client.LogicClient`; он использует стандартную библиотеку Python. Порядок интеграции и поля ошибок — в [API_CONTRACT.md](docs/API_CONTRACT.md). Vue-интерфейс подключен через браузерный шлюз; пользовательская авторизация и команды реализованы в режиме `accounts`.

Приемка v0.2.0: два публичных проекта прошли HTTP-путь, сохранение и восстановление решений, экспорт и повторение в чистых venv. Исходные результаты совпали; оба сгенерированных Dockerfile собраны и запущены без сети. Решения пережили перезапуск контейнера, повторный анализ и stale-защита проверены на VM. Доказательства: [workflow-verification.json](examples/workflow-verification.json).
